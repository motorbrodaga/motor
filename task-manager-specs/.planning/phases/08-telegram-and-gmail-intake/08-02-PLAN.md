# 08-02: Implement Gmail Search And 20-Result Selection Flow

## Objective

Let the user explicitly search Gmail from the import area, review up to 20 matching email choices, and select one for task preparation.

## Context To Read

- `.planning/phases/08-telegram-and-gmail-intake/08-CONTEXT.md`
- `.planning/phases/08-telegram-and-gmail-intake/08-RESEARCH.md`
- `.planning/REQUIREMENTS.md`
- `zadachnik-app/src/app/(app)/more/page.tsx`
- `zadachnik-app/src/app/api/assistant-capture/interpret/route.ts`

## Implementation Tasks

1. Add a Gmail import tab or section under the deliberate import area.
2. Require a non-empty user-written search query before requesting Gmail choices.
3. Define a narrow Gmail adapter interface for the app runtime: search query in, sanitized email choices out.
4. Cap displayed Gmail choices at 20.
5. Show compact email rows with subject, sender, date, snippet, and source label `from Gmail`.
6. Add graceful unavailable/error UI if Gmail is not configured for the app runtime.
7. Ensure selecting an email passes only the chosen source into the shared intake confirmation flow.

## Acceptance Criteria

- Gmail import is reachable from "More", not from quick capture.
- Empty Gmail search does not query anything.
- Search results are capped at 20 visible choices.
- User selects one email before a task draft is prepared.
- Opening Gmail import or running search never creates a task.

## Verification

- Run focused Gmail adapter tests using deterministic fixtures/mocks.
- Run focused import UI tests for query, empty state, error state, and 20-result cap.
- Run `npm run typecheck`.
