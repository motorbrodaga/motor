# 08-05: Add Privacy And Explicit-Request Safeguards

## Objective

Create the shared guardrails for Phase 8: import actions require explicit user intent, provider calls are capped, and no background Telegram/Gmail scanning is introduced.

## Context To Read

- `.planning/phases/08-telegram-and-gmail-intake/08-CONTEXT.md`
- `.planning/PROJECT.md`
- `.planning/REQUIREMENTS.md`
- `AGENTS.md`
- `zadachnik-app/src/app/(app)/more/page.tsx`
- `zadachnik-app/src/app/api/assistant-capture/interpret/route.ts`
- `zadachnik-app/tests/helpers/access.ts`

## Implementation Tasks

1. Add the import entry under "More" with Russian-only labels that communicate a deliberate user action.
2. Add shared request validation requiring explicit provider action, source type, and user search query where applicable.
3. Enforce provider result limits server-side, not only in UI.
4. Ensure no scheduled job, background route, page load, or automatic inbox scan reads Telegram/Gmail.
5. Keep provider errors private and user-facing messages calm; do not expose secret paths, tokens, session strings, or raw stack traces.
6. Add tests for empty/implicit requests, excessive limits, and no-create-before-confirmation behavior.
7. Document the privacy boundary in the Phase 8 summary after execution.

## Acceptance Criteria

- Import is user-triggered from "More".
- Telegram and Gmail provider routes reject implicit or unbounded requests.
- Search/opening source lists never creates tasks.
- No background scanning code is added.
- Errors do not leak Telegram/Gmail secrets or local session paths.

## Verification

- Run focused privacy guardrail tests.
- Search code for accidental background scanner patterns.
- Run `npm run typecheck`.
