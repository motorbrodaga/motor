# 10-03: Implement Automatic Backup And Recovery Path

## Objective

Protect task data with automatic backups and a clear recovery path that can restore the MVP task database if something goes wrong.

## Context To Read

- `.planning/phases/10-offline-conflicts-and-backups/10-RESEARCH.md`
- `.planning/phases/10-offline-conflicts-and-backups/10-01-PLAN.md`
- `.planning/phases/10-offline-conflicts-and-backups/10-02-PLAN.md`
- `.planning/REQUIREMENTS.md`
- `zadachnik-app/prisma/schema.prisma`
- `zadachnik-app/src/lib/db.ts`
- `zadachnik-app/package.json`
- `zadachnik-app/.gitignore`

## Implementation Tasks

1. Add a backup exporter that reads recoverable Prisma data and writes timestamped JSON with schema version, creation timestamp, entity counts, and data payload.
2. Include task-domain data needed to recover the MVP: tasks, notes, categories, contexts, task-context links, projects, focus selections, calendar-link metadata, notification preferences, and safe app settings.
3. Exclude `.env`, Telegram sessions, raw private tokens, downloaded personal files, and any generated backup output from git.
4. Add backup metadata storage, either as a `BackupRun` model or a structured `AppSetting`, recording last success, last failure, file path/name, and counts.
5. Add a scheduled/manual runner path. A script is acceptable for automation; a small More/settings status panel is useful for manual verification.
6. Add backup retention rules so local backups do not grow forever.
7. Add a restore validation script that checks version, required sections, and entity consistency before any import.
8. Add an intentional restore/import script or documented command path that can recover into a database after validation. Keep destructive restore out of the everyday phone UI.

## Acceptance Criteria

- The system can create an automatic backup file without user interaction.
- The user can see whether the latest backup succeeded.
- A manual backup run can be triggered for verification.
- Backup files are stored in a git-ignored location and are not added to commits.
- Restore validation can confirm a backup is usable or explain why it is not.
- The recovery path is documented in Russian for the user.

## Verification

- Add tests for backup JSON shape, entity counts, safe exclusions, and retention behavior.
- Add tests for restore validation on valid and invalid backup files.
- Run a local backup against test data and confirm the output path is ignored by git.
- Run `npm run typecheck`.
