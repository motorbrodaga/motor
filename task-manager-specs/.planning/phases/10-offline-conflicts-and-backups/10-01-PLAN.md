# 10-01: Implement Offline Task Storage And Sync Queue

## Objective

Let the user keep working with core tasks on the phone while offline by caching task data locally and queuing task changes for later sync.

## Implementation Tasks

1. Add a small IndexedDB module for task cache and queued mutations with schema versioning.
2. Cache task list/detail responses used by Dashboard, Inbox, Waiting, Review, and task detail where those screens already load task data.
3. Add a mutation queue envelope for task create, task patch, task archive/delete, quick actions, and note creation.
4. Wrap task-writing UI flows so they try the API first, then queue locally when offline or when the request clearly fails because the network is unavailable.
5. Make queued local changes update the visible local cache immediately so the phone stays useful offline.
6. Extend `public/sw.js` to cache the app shell and static assets needed to reopen the main app routes while offline.
7. Add a small Russian sync indicator for states such as `Офлайн`, `Ждет синхронизации`, `Синхронизировано`, and `Нужно проверить`.
8. Add a reconnect/background flush trigger that attempts to send queued mutations when the browser comes back online.
9. Keep Telegram/Gmail import, calendar feed updates, and push delivery online-only in this plan unless they naturally reuse the task queue without extra scope.

## Acceptance Criteria

- The user can open the app on a phone-sized viewport after previously loading it, switch offline, and still see cached task screens.
- The user can create a quick task while offline and see it in the local task list immediately.
- The user can edit/complete/archive an existing cached task while offline and see the local result immediately.
- Queued changes survive a browser reload.
- Returning online sends queued changes to the server and clears successfully applied queue items.
- The UI explains offline/sync state in plain Russian without showing raw technical errors.

## Verification

- Add unit tests for IndexedDB queue serialization and local cache updates.
- Add focused browser tests for offline quick-create, offline edit, reload survival, reconnect sync, and visible sync status.
