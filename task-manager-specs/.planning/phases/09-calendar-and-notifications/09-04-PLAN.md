# 09-04: Add Optional Web Push Notification Foundation

## Objective

Add the app foundation for real optional PWA push notifications: preferences, permission flow, subscription storage, service worker handling, and server-side send support.

## Context To Read

- `.planning/phases/09-calendar-and-notifications/09-CONTEXT.md`
- `.planning/phases/09-calendar-and-notifications/09-RESEARCH.md`
- `zadachnik-app/prisma/schema.prisma`
- `zadachnik-app/src/app/manifest.ts`
- `zadachnik-app/src/app/(app)/more/page.tsx`

## Implementation Tasks

1. Add notification preferences under "More" for morning review and task reminders.
2. Add push subscription storage with endpoint, keys, enabled state, timestamps, and device/browser label.
3. Add a client permission flow triggered by a user tap, with unsupported and denied states.
4. Add a service worker push handler that displays visible notifications and opens the app to the right screen.
5. Add server-side web-push send helper configuration with missing-config fallback states.
6. Add VAPID/public key plumbing without committing private keys.
7. Add tests for disabled preferences, unsupported browser, denied permission, stored subscription, and unsubscribe/disable.

## Acceptance Criteria

- The user can enable or disable morning review notifications.
- The user can enable or disable individual task reminders.
- The app stores real push subscriptions only after permission is granted.
- Unsupported iOS/browser states are shown clearly and do not break the app.
- No private push keys are committed or printed.

## Verification

- Run notification settings tests.
- Run service worker registration tests where supported by the test setup.
- Run `npm run typecheck`.
