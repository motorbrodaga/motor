# 09-01: Implement Subscribed iPhone Calendar Feed Foundation

## Objective

Create the durable calendar foundation: a private subscribed iCalendar feed, stable event identifiers, and data storage that can support linked task updates.

## Context To Read

- `.planning/phases/09-calendar-and-notifications/09-CONTEXT.md`
- `.planning/phases/09-calendar-and-notifications/09-RESEARCH.md`
- `.planning/REQUIREMENTS.md`
- `zadachnik-app/prisma/schema.prisma`
- `zadachnik-app/src/app/api/tasks/[id]/route.ts`
- `zadachnik-app/src/app/manifest.ts`

## Implementation Tasks

1. Add structured calendar storage: a private calendar feed token and a task calendar-link record with stable event UID, sequence, all-day/timed fields, and include-description/include-notes flags.
2. Add a server route that returns `text/calendar` for the private feed URL.
3. Generate valid iCalendar `VCALENDAR` / `VEVENT` output for linked tasks, including stable `UID`, title, start/end, `DTSTAMP`, `LAST-MODIFIED`, and `SEQUENCE`.
4. Add a token regeneration path that invalidates old calendar feed URLs.
5. Add a small server-side iCalendar helper with escaping/line-folding tests instead of ad hoc string assembly in route code.
6. Keep any one-off `.ics` export as a fallback only; the primary path should be the subscribed feed URL.

## Acceptance Criteria

- The app has a private calendar feed URL that can be copied/subscribed on iPhone.
- Linked tasks appear in the feed as stable iCalendar events.
- Regenerating the calendar token invalidates the old feed.
- Calendar feed access does not depend on the normal browser session cookie.
- The implementation does not log or expose the private feed token except where the user intentionally views/copies it.

## Verification

- Run token regeneration tests.
