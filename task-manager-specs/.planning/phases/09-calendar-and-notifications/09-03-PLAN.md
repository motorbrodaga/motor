# 09-03: Update Linked Calendar Events When Tasks Change

## Objective

Keep linked calendar feed events in sync with task edits by updating event metadata and sequence fields whenever relevant task fields change.

## Context To Read

- `.planning/phases/09-calendar-and-notifications/09-CONTEXT.md`
- `.planning/phases/09-calendar-and-notifications/09-RESEARCH.md`
- `.planning/phases/09-calendar-and-notifications/09-01-PLAN.md`
- `.planning/phases/09-calendar-and-notifications/09-02-PLAN.md`
- `zadachnik-app/src/app/api/tasks/[id]/route.ts`
- `zadachnik-app/src/lib/tasks/task-validation.ts`

## Implementation Tasks

1. Identify task fields that affect the calendar event: title, description, notes inclusion, date/time, status, and deletion/archive behavior.
2. On relevant task updates, refresh the linked event projection and increment its sequence.
3. If a linked task is completed, archived, or deleted, apply the chosen MVP behavior consistently: remove from feed or mark as cancelled.
4. Show last calendar update status on task detail so the user can tell the link is still active.
5. Add a manual refresh/copy fallback only for cases where the subscribed calendar client has not refreshed yet.
6. Add regression tests proving unchanged edits do not create unnecessary sequence bumps.

## Acceptance Criteria

- Editing a linked task changes the corresponding event in the feed.
- Calendar event `SEQUENCE` changes only when calendar-relevant data changes.
- Completed/archived/deleted linked tasks have a defined feed behavior.
- The UI honestly communicates that iPhone Calendar refresh timing is controlled by the calendar client.
