# 05-02: Build Waiting Screen And Response Date Flow

## Objective

Replace the placeholder waiting page with a usable, grouped view of people-related waiting tasks, and make the separate response date visible for tasks where someone waits for the user.

## Context To Read

- `.planning/phases/05-waiting-and-people/05-CONTEXT.md`
- `.planning/phases/05-waiting-and-people/05-RESEARCH.md`
- `zadachnik-app/src/app/(app)/waiting/page.tsx`
- `zadachnik-app/src/features/tasks/TaskForm.tsx`
- `zadachnik-app/src/features/tasks/TaskCard.tsx`
- `zadachnik-app/src/lib/tasks/task-queries.ts`
- `zadachnik-app/src/lib/dashboard/dashboard-sections.ts`
- Phase 4 dashboard tests for list/card patterns

## Implementation Tasks

1. Add a waiting query/helper that returns open, unarchived tasks with both `personLabel` and `waitingDirection`.
2. Group waiting tasks into `ждут от меня` and `я жду` sections.
3. Add response due date editing for `ждут от меня` tasks as a separate field from `dueDate` and `doDate`.
4. Display response due date on cards and on the waiting page with a distinct Russian label.
5. Replace the placeholder `/waiting` page with grouped lists, empty states, and task cards or compact task rows that match the current app style.
6. Keep completed and archived tasks out of the waiting page.
7. Update Dashboard waiting section logic to use person plus direction rather than any person label.

## Acceptance Criteria

- `/waiting` shows two understandable groups: `ждут от меня` and `я жду`.
- Tasks appear only when both a person and a waiting direction are set.
- `ждут от меня` tasks can have a separate response due date.
- Response due date does not overwrite normal due date or do date.
- Completed and archived tasks do not appear in waiting lists.
- Dashboard waiting state follows the same derived waiting rule.

## Verification

- Add or update tests for waiting grouping, response due date, and exclusion of done/archived tasks.
- Update Dashboard section tests for the new waiting rule.
- Run Playwright mobile smoke for `/waiting`.
- Run `npm test` in `zadachnik-app`.
