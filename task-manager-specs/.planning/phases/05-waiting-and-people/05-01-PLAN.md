# 05-01: Add Waiting Fields To Tasks

## Objective

Extend the task model, validation, and existing task edit surfaces so a task can keep a person label and an explicit waiting direction. This creates the foundation for the waiting screen without introducing contacts or a separate people directory.

## Context To Read

- `.planning/phases/05-waiting-and-people/05-CONTEXT.md`
- `.planning/phases/05-waiting-and-people/05-RESEARCH.md`
- `.planning/REQUIREMENTS.md`

- `zadachnik-app/src/features/tasks/TaskQuickActions.tsx`
- `zadachnik-app/src/features/tasks/TaskCard.tsx`

## Implementation Tasks

1. Add nullable waiting fields to `Task`: direction, separate response due date, and a stable waiting-start date.
2. Generate and apply the Prisma migration, then regenerate the Prisma client if needed.
3. Extend task TypeScript view types and query serialization so the new fields are available wherever task cards and forms render.
4. Extend task validation so only supported waiting-direction values are accepted, blank values clear the field, and response due dates parse like other date fields.
5. Set or update `waitingSince` when a task first receives a waiting direction or changes direction. Preserve it for unrelated edits.
6. Extend `TaskForm` with a mobile-friendly direction control near the person field, using Russian labels.
7. Extend `TaskQuickActions` so a person can be assigned together with either `ждут от меня` or `я жду`.
8. Extend `TaskCard` to show person plus waiting direction in a compact, readable signal.

## Acceptance Criteria

- A task can store a plain person name and one of two waiting directions.
- The UI uses only the labels `ждут от меня` and `я жду` for the directions.
- Adding a person alone does not make the task a waiting task; direction is required.
- The task card shows the person and direction clearly on mobile.
- Existing tasks without waiting fields still render and edit normally.
