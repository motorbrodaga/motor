# 07-03: Connect History To Task Completion And Manual Actual-Time Entry

## Objective

Make completion history durable and editable: completing a task should reliably place it in history, and completed task rows should allow optional later actual-time entry.

## Implementation Tasks

1. Audit every existing "mark done" path.
2. Ensure changing a task to `done` sets `completedAt` if it was empty.
3. Ensure moving a task out of `done` clears or handles `completedAt` consistently with the existing task lifecycle.
4. Confirm `actualMinutes` is accepted by task validation and constrained to a sensible non-negative integer.
5. Add a small client component for editing actual time from completed task rows.
6. Keep the action optional: no modal or prompt should appear immediately after completion.
7. Refresh or revalidate the history page after saving actual time.
8. Add tests covering completion timestamp behavior and manual time entry.

## Acceptance Criteria

- A newly completed task appears in completion history.
- User can add or update actual time from the history/completed task surface.
- Completion does not force the user to answer a time question.
- Actual time appears in the task row and contributes to history statistics.
- Invalid actual time values are rejected or normalized safely.
