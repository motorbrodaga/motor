# Задачник

## What This Is

Задачник — личный таск-менеджер для одного пользователя, который заменяет ненадежную память и разрозненные заметки внешней системой управления задачами, сроками, ожиданиями и дневным фокусом. Первая версия должна работать с телефона и компьютера с общей актуальной базой задач, но главный сценарий должен быть удобен именно на телефоне.

Продукт строится вокруг мягкого возврата задач в поле внимания: быстрый захват, диалоговое уточнение через ассистента, утренняя панель с главными задачами дня, ожидания по людям и еженедельный обзор забытых или зависших задач.

## Core Value

Не дать задачам потеряться.

### Active

- [ ] Пользователь может быстро создать задачу из короткой формулировки без обязательного заполнения проекта, срока и приоритета.
- [ ] Пользователь может редактировать, закрывать, удалять или архивировать задачи.
- [ ] Задача хранит название, категорию, статус, важность, срочность, срок, день выполнения, примерное время, связанного человека, описание и заметки.
- [ ] Система различает важность и срочность; срочность является бинарным полем.
- [ ] Система различает день выполнения и крайний срок.
- [ ] Пользователь может работать с базовыми категориями: работа, личное, звонки, бытовое.
- [ ] Пользователь может создавать собственные цветные категории.
- [ ] Пользователь может назначать один или несколько контекстов выполнения: звонок, компьютер, дом, в дороге, с человеком.
- [ ] Пользователь может создавать собственные контексты.
- [ ] Ассистент помогает уточнять задачу через диалог или показывает, как понял задачу, перед сохранением.
- [ ] Если часть полей неизвестна, задача может быть сохранена с пустыми полями после подтверждения пользователя.
- [ ] Главный экран показывает панель: сегодня, просроченное, ожидания, важное без срока и категории.
- [ ] Утренняя панель предлагает 3 главные задачи дня.
- [ ] Пользователь подтверждает предложенные 3 задачи дня или вручную заменяет любую из них.
- [ ] Если пользователь не подтвердил предложенные 3 задачи, они остаются предложением, а не выбранными задачами.
- [ ] Рядом с 3 главными задачами есть блок "остальное на сегодня".
- [ ] Система повышает вес задач, где кто-то ждет пользователя, и учитывает срочность выше важности.
- [ ] Просроченные задачи попадают в топ-3 только если они важные или срочные.
- [ ] Система поддерживает ожидания в двух направлениях: "ждут от меня" и "я жду от других".
- [ ] Для задач "ждут от меня" можно задать срок ответа.
- [ ] Для задач "я жду от других" без срока система мягко напоминает проверить статус через неделю.
- [ ] Задачи без срока возвращаются в внимание раз в неделю.
- [ ] Еженедельный обзор по понедельникам показывает забытые, зависшие, бессрочные задачи, задачи без дня выполнения, ожидания без движения и категории с накопившимися задачами.
- [ ] Зависшая задача определяется как задача без изменений 7 дней.
- [ ] История выполненного показывает выполненные задачи за сегодня и за неделю.
- [ ] История выполненного включает небольшую статистику: количество задач, распределение по категориям и фактически потраченное время.
- [ ] Фактическое время пользователь вводит вручную; таймер старт/стоп не входит в первую версию.
- [ ] Карточка задачи поддерживает быстрые действия: выполнить, перенести, изменить важность, добавить заметку, назначить человека.
- [ ] Перенос задачи поддерживает быстрые варианты: завтра, через неделю, выбрать дату.
- [ ] Заметки к задаче представлены лентой заметок/комментариев, а не одним перезаписываемым полем.
- [ ] Приложение поддерживает сбор задач из Telegram по явной просьбе пользователя через чат `https://t.me/Motorcodex_bot`.
- [ ] При импорте из Telegram система показывает 20 последних сообщений на выбор.
- [ ] Приложение поддерживает сбор задач из Gmail по явной просьбе пользователя.
- [ ] При поиске письма Gmail система показывает до 20 найденных вариантов на выбор.
- [ ] При импорте из Telegram/Gmail ассистент готовит карточку задачи для подтверждения.
- [ ] Telegram-сообщение кратко пересказывается в задаче, а не копируется целиком.
- [ ] Для источника Telegram/Gmail достаточно текстовой пометки; ссылку на исходное письмо или сообщение хранить не нужно.
- [ ] Приложение доступно с телефона и компьютера с одной актуальной базой задач.
- [ ] На телефоне продукт должен ощущаться как приложение, насколько это возможно для выбранного стека.
- [ ] MVP использует простой персональный доступ через приватную ссылку.
- [ ] Приватную ссылку можно перегенерировать.
- [ ] Нужна офлайн-работа на телефоне.
- [ ] При офлайн-конфликтах побеждает последняя версия изменения.
- [ ] Нужны автоматические бэкапы.
- [ ] Push-уведомления входят в MVP, но являются опциональными для утреннего обзора и других задач.
- [ ] Пользователь может добавить задачу в календарь iPhone.
- [ ] При изменении задачи связанное событие календаря iPhone должно обновляться.
- [ ] Нижнее мобильное меню первой версии: Панель, Входящие, Ожидания, Обзор, Еще.

### Out of Scope

- Командные роли — первая версия предназначена только для одного пользователя.
- Общий доступ — MVP использует персональный доступ, а не многопользовательскую модель.
- Многопользовательские сценарии — слишком расширяют продуктовую и техническую область первой версии.
- Тяжелая командная работа — не соответствует основной личной задаче MVP.
- Перегруженная проектная методология — первая версия должна оставаться простой и доводимой до рабочего состояния.
- Теги — не входят в первую версию.
- Вложения к задачам — не входят в MVP.
- Голосовой ввод с телефона — не нужен в первой версии.
- Таймер старт/стоп — фактическое время вводится вручную.
- Отдельный архив выполненных задач — достаточно истории выполненного.
- Отдельная метка "ждет человек" — ожидание определяется через связанного человека и направление ожидания.
- Подзадачи — полезны через диалог, но могут быть отложены на вторую итерацию.
- Повторяющиеся задачи — продуктово нужны, но могут быть отложены после первой рабочей версии.

## Context

Сейчас пользователь ведет задачи в памяти и заметках. Основная боль: задачи не находятся, забываются и теряются. Система должна быть не просто хранилищем, а способом регулярно возвращать важное в поле внимания и помогать принимать решение, что делать сейчас.

Первая версия строится для личного использования. Возможные будущие аудитории: семья, рабочие проекты, команда или агентная система, где задачи ставятся и обрабатываются AI-агентами. Эти сценарии не должны усложнять MVP.

Корневая папка проекта содержит спецификации: `01-product-vision.md`, `02-requirements.md`, `03-domain-model.md`, `04-ux-flows.md`, `05-tech-decisions.md`, `06-open-questions.md`, `07-development-brief.md`, `08-spec-audit.md`. Разработка приложения еще не начиналась.

В этой же рабочей области есть вложенный пакет `gsd-get-shit-done/`, но карта кодовой базы фиксирует, что это существующая GSD-система, а не реализация Задачника. Для будущей разработки важно явно отделять работу над спецификациями Задачника от изменений в `gsd-get-shit-done/`.

Интеграции с Telegram/Gmail должны работать только по явной просьбе пользователя. Для Telegram в MVP используется чат `https://t.me/Motorcodex_bot`, а не Saved Messages. При работе с локальным Telegram-доступом нельзя печатать `.env` и `.telegram_sessions/chief_agent.session.txt`.

## Constraints

- **Audience**: один пользователь в MVP — командные роли и общий доступ исключены, чтобы не раздувать первую версию.
- **Device**: главный сценарий должен работать с телефона — интерфейс и быстрый захват задач должны проектироваться mobile-first.
- **Cross-device**: телефон и компьютер должны видеть одну актуальную базу — нужно выбрать способ хранения и синхронизации.
- **Offline**: нужна офлайн-работа на телефоне — архитектура должна поддерживать локальное состояние и синхронизацию.
- **Conflict policy**: при офлайн-конфликтах побеждает последняя версия изменения — простое правило важнее сложного merge в MVP.
- **Access**: персональный доступ через приватную ссылку — нужна возможность перегенерировать ссылку.
- **Backups**: нужны автоматические бэкапы — потеря задач противоречит core value.
- **Notifications**: push-уведомления остаются в MVP, но должны быть опциональными — мягкие обзоры важнее жесткого давления.
- **Calendar**: нужна интеграция с календарем iPhone — способ интеграции еще нужно выбрать перед реализацией.
- **Telegram/Gmail privacy**: задачи создаются только по явной просьбе пользователя — система не сканирует всю переписку автоматически.
- **Project state**: проект находится внутри внешнего git worktree `C:/Users/maksd/OneDrive/Документы/New project 2` — git-операции должны учитывать внешний корень.
- **GSD agents**: нужные GSD subagents не установлены в проверенном runtime — дальнейшие research/roadmap шаги могут выполняться inline.
